What we found

Product images without alt text — 5 found (severity high, WCAG 1.1.1)

Screen-reader users hear nothing (or a filename) for these images. Missing alternative text is the single most common allegation in ADA complaints against online stores.

  • <img src="products/hero-banner.jpg">: img has no alt attribute (alt="" would mark it decorative) — store_bad_SYNTHETIC.html
  • <img src="products/tshirt-red.jpg">: img has no alt attribute (alt="" would mark it decorative) — store_bad_SYNTHETIC.html
  • <img src="products/tshirt-blue.jpg">: img has no alt attribute (alt="" would mark it decorative) — store_bad_SYNTHETIC.html
  • ...and 2 more like these.

How to fix: Add a short description of what the image shows to each img tag's alt attribute. Purely decorative images should get an empty alt="" instead.

Form fields without labels — 2 found (severity high, WCAG 1.3.1)

Checkout and search fields with no programmatic label force assistive-technology users to guess what to type. Checkout blockers are the second most common allegation class in e-commerce filings.

  • <input name="q">: form control has no <label>, aria-label, or title (placeholder is not a label) — store_bad_SYNTHETIC.html
  • <select name="size">: form control has no <label>, aria-label, or title — store_bad_SYNTHETIC.html

How to fix: Associate a <label for="..."> with each field, or add an aria-label. Placeholder text disappears on input and does not count as a label.

Text failing contrast (inline styles) — 1 found (severity high, WCAG 1.4.3)

Text below the 4.5:1 contrast minimum is unreadable for low-vision users — and often for anyone on a phone in sunlight.

  • <p>: inline style #888888 on #ffffff = 3.54:1 (AA needs 4.5:1) — store_bad_SYNTHETIC.html

How to fix: Darken the text color or lighten the background until the pair reaches 4.5:1. The attached patch proposes minimal color changes.

Theme colors failing contrast — 4 found (severity high, WCAG 1.4.3)

Theme stylesheet rules that render text below the 4.5:1 AA minimum against their declared background.

  • .btn-primary: #9aabbc on #ffffff = 2.35:1 (AA needs 4.5:1) — theme_bad_SYNTHETIC.css
  • .hero-banner h2: #ffffff on #e8e8e8 = 1.23:1 (AA needs 4.5:1) — theme_bad_SYNTHETIC.css
  • .footer a: #6699cc on #ffffff = 3.00:1 (AA needs 4.5:1) — theme_bad_SYNTHETIC.css
  • ...and 1 more like these.

How to fix: Apply the attached override stylesheet, or adjust the theme's color settings. Each line in the patch keeps your brand hue and moves lightness the minimum distance needed.

Buttons with no accessible name — 1 found (severity high, WCAG 4.1.2)

Icon-only buttons (cart, search, close) with no text or aria-label are announced as just 'button' — the user cannot know what it does.

  • <button class="search-btn">: button has no text and no aria-label — store_bad_SYNTHETIC.html

How to fix: Add an aria-label describing the action, e.g. aria-label="Add to cart".

Links with no accessible name — 1 found (severity high, WCAG 2.4.4)

Icon-only links with no text or aria-label are announced as just 'link' — navigation becomes guesswork.

  • <a href="/cart">: link has no text and no aria-label (icon-only?) — store_bad_SYNTHETIC.html

How to fix: Add an aria-label to icon links, e.g. aria-label="View cart".

Mouse-only interactive elements — 1 found (severity med, WCAG 2.1.1)

Elements that react to clicks but aren't real buttons or links can't be reached or activated with a keyboard. Keyboard-access failures are a core allegation in most ADA web complaints.

  • <div>: <div> has onclick but no role/tabindex — unreachable by keyboard — store_bad_SYNTHETIC.html

How to fix: Use a real <button> or <a>, or add role="button" tabindex="0" plus a keydown handler.

Broken focus order — 1 found (severity med, WCAG 2.4.3)

Positive tabindex values force keyboard focus to jump around the page in an author-defined order that rarely matches the visual order.

  • <a href="/faq">: tabindex=3 overrides natural focus order — store_bad_SYNTHETIC.html

How to fix: Remove positive tabindex values; use DOM order (tabindex="0" is fine).

Pinch-zoom disabled — 1 found (severity med, WCAG 1.4.4)

The viewport meta tag blocks zooming, locking out low-vision users on mobile — where most store traffic is.

  • <meta name="viewport">: viewport blocks zoom: content="width=device-width, initial-scale=1.0, user-scalable=no" — store_bad_SYNTHETIC.html

How to fix: Remove user-scalable=no and any maximum-scale below 2 from the viewport meta tag.

Alt text that is a filename or placeholder — 2 found (severity med, WCAG 1.1.1)

Alt text like "IMG_1234.jpg" is worse than useless — screen readers read it out character by character.

  • <img src="products/IMG_1234.jpg">: alt looks like junk/filename: "IMG_1234.jpg" — store_bad_SYNTHETIC.html
  • <img src="products/candle.jpg">: alt looks like junk/filename: "image" — store_bad_SYNTHETIC.html

How to fix: Replace with a short human description of the image.

Generic link text — 2 found (severity med, WCAG 2.4.4)

"Click here" and "read more" convey nothing when screen-reader users navigate by a list of links, which is how most navigate long pages.

  • <a href="/sale">: link text "click here" is meaningless out of context — store_bad_SYNTHETIC.html
  • <a href="/blog">: link text "read more" is meaningless out of context — store_bad_SYNTHETIC.html

How to fix: Make link text describe the destination: "Read our shipping policy".

Untitled embedded frames — 1 found (severity med, WCAG 4.1.2)

Embedded frames (reviews widgets, videos, maps) without a title are announced with no context.

  • <iframe src="https://reviews.example.com/widget">: iframe has no title attribute — screen readers announce nothing useful — store_bad_SYNTHETIC.html

How to fix: Add title="..." describing the frame's content, e.g. title="Customer reviews".

Skipped heading levels — 1 found (severity low, WCAG 1.3.1)

Heading levels that jump (h1 to h3) break the page outline that screen-reader users navigate by.

  • <h3>: heading level jumps h1 -> h3 — store_bad_SYNTHETIC.html

How to fix: Keep heading levels sequential; style size with CSS, not by picking a smaller heading tag.

Page language not declared — 1 found (severity low, WCAG 3.1.1)

Without a lang attribute, screen readers guess the pronunciation language — sometimes wrongly.

  • <html>: html tag has no lang attribute (SC 3.1.1) — store_bad_SYNTHETIC.html

How to fix: Add lang="en" (or the store's language) to the html tag.

How this estimate works — and what it can't see

This scan statically analyzes the HTML and CSS your store serves. It checks

machine-verifiable WCAG 2.1 criteria: image alternative text, form labels,

color contrast (where both colors are declared), keyboard-access patterns,

link/button naming, zoom blocking, frame titles, language and page-title

metadata, and heading structure.

What it cannot see: content rendered or repaired by JavaScript after page

load, contrast of text over images or gradients, focus-visibility styling,

media captions, and anything requiring human judgment about meaning. A clean

result here is a good signal, not a clean bill of health, and issues listed

under "review suggested" were measured against assumed backgrounds and need a

human look before acting.

Scoring: each confirmed issue class contributes points weighted by severity,

by how often that failure class appears in real ADA e-commerce complaints,

and (with diminishing returns) by how many instances were found. The 0-100

scale is an internal yardstick for prioritization between stores and scans —

it is not a legal measurement.
